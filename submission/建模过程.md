# 正式提交的建模过程

最终任务是站在 2025-09-01，为官方名单里的每位读者列出十个可能首次借阅的索书号。入口 `train.py` 运行下表第 1 至 5 步，`predict.py` 加载训练好的参数运行推荐，`verify.py --check-reference` 核对结果。命令均在解压后的项目目录执行。

| 从输入到结果 | 实际处理 | 对应源码与产物 |
|---|---|---|
| 1. 清洗历史借阅 | 从 Excel 定位真实表头，保留借书记录，规范读者条码、图书条码和时间，处理缺失、重复与冲突。清洗结果共 29,857 行，其中 29,841 行有有效索书号并进入事件模型。 | `preprocess.py`、`pipeline.prepare` → `work/processed/borrowing_cleaned.csv`；清洗时还输出字段质量与汇总指标 |
| 2. 构建目录和图书特征 | 按索书号整合历史书目、官方新入藏目录、读者清单里的历史题名，标记记录来源与冲突。共 21,030 条书目；最终合法候选取历史借阅和新入藏目录的并集。验证清单中特有的历史条目可用于表示读者。 | `build_book_catalog.py`、`event_training.official_meta`、`event_network.make_bank` → `work/catalog.csv` 与书特征 |
| 3. 构造训练查询 | 只用观测到的历史流水构造训练标签。相邻借阅间隔不超过 30 分钟合为一次事件，事件内按索书号去重。在预测点之前建立前缀，正例剔除读者此前已借过的全部索书号。 | `event_sequences.py` → 5,107 位读者、13,686 个事件、12,229 个下一事件查询、8,839 个双月查询 |
| 4. 训练读者塔与图书塔 | 输入历史事件、读者画像与书目特征，联合优化两个任务。用训练完成的书塔和读者塔参数及候选书特征共同重建向量检索。 | `event_network.EventNet`、`event_training.batch_loss/fit_fold` → `models/event.pt`、`models/event_manifest.json` |
| 5. 为验证名单生成 Top-10 | 从截止前历史建立热门、学院、共现、同作者/分类等基础统计；有历史读者再融合双塔排名。按原名单次序输出两列 CSV。逐人核验条数、索书号去重、合法性、完整个人书单排除和文件哈希。 | `base_rank.py`、`older_call_recall.py`、`newcomer_portrait.py`、`pipeline.predict`、`verify.py` → `验证集结果.csv` |

## 特征、监督信号和推荐策略

**书向量。** 本地冻结的 BGE 根据题名生成 512 维向量。责任者、出版社、中图分类前缀、五年一档的出版年份各提供 8 维嵌入；多主题特征占 36 维，普通多主题按标签数均分权重。拼接后经 580 → 96 → 64 的网络并归一化。已有标注在 `inputs/topics.jsonl`，编号定义在 `book_topics_v2.json`，生成标注所用的提示词见 [主题标注提示词](evidence/主题标注提示词.md)。主题是事先根据书目获得的输入；正式训练读取已交付标注，词表、编号格式和冲突处理有对应代码。

**标注准备与校验。** 如需审查外部大模型的主题标注环节，在新解压的项目目录依次运行以下命令。第一条从随包数据生成书目底表和来源明细，第二条生成标注输入，第三条把实际采用的 JSONL 与索书号集合和固定词表逐项核对并解码。目录和输出文件请选择空闲路径，避免覆盖已有标注。

```powershell
python build_book_catalog.py --out data/book_catalog
python book_topic_batch.py prepare --start 1 --size 21030 work/topic_batch.json
python book_topic_batch.py decode work/topic_batch.json inputs/topics.jsonl work/topic_check.csv
```

**读者向量。** 训练使用最近八次真实事件，事件内对书向量取平均，单层 64 维 GRU 按顺序读取事件表示。模型还接收最近一次的书向量、专业、学院、在读年级、读者级别、性别及历史规模、最近借阅间隔、输入视图标记。训练中约半数样本使用与官方相同的有序去重书单视图，另以 20% 概率隐藏历史。正式推断使用官方书单末尾最多八本，排除已借时使用整张书单。

**训练。** 下一事件与完整两个月窗口两种任务等概率抽样，每个任务内先抽读者，再抽查询。每个有效样本抽 1 本新借正例和 12 本在当时已可见的负例，优先抽同类，并排除已借书和该查询的所有正例。读者与候选书向量的点积乘以 10 后计算交叉熵。使用 AdamW、学习率 0.001、批大小 96、种子 2026。正式历史最后一笔为 2025-01-16；2025-09-01 是名单的预测起点。名单中的属性和历史书单是预测输入；监督标签来自截止前的训练流水。

**融合。** 345 位有历史读者的两个通道各取前 100，本书出现在某榜第 r 位就获得 权重/(20+r) 分，基础榜权重 1，事件榜 0.5。610 位无历史新人使用画像群体偏好，样本不足时回退到热门；1 位无历史老人使用近期热门。仅入藏目录出现的书可被书塔编码并进入事件榜；本次最终前十中这类书有 0 本，原因与实测候选数见 README。

## 为什么选择 8 轮

用三个全局时间点模拟正式预测，每个开发窗以之后两个月首次新借的索书号为答案。每窗分别使用种子 2026、2027，固定实际提交的融合与冷启动策略。在同一条训练轨迹的 8、12、16 轮分别评估。三个窗口和两个种子等权，平均综合分分别是 7.834、7.725、7.715，故将 8 轮写入正式配置。八轮正式模型的逐轮训练损失见 `models/event_manifest.json`。这些分数属于历史回放；组委会负责正式验证集评分。

运行 `python replay_epochs.py`，程序从清洗流水重建个人已见集合、未来答案和新老分组，对 `evidence/dev_top10.csv.gz` 里的 7,290 条历史预测重新计算 Hit@10、Recall@10 和 NDCG@10，再核对 `epoch_scores.csv` 中的全部分组和总分。此命令复算选型依据，正式模型重训入口为 `python train.py`。

## 如何验证原始输入足够重建模型

`python train.py` 每次重新清洗、采样并从随机初值优化双塔。已有冻结题名向量且指纹匹配时，程序会复用这些向量。要检验从原始输入重新编码题名的路径，可在新建的空目录中复制项目根目录的 Python 文件、`config.json`、`book_topics_v2.json`、`reference.sha256`、整个 `inputs` 及 `models/bge`（保留相同相对路径），然后在该目录执行：

```powershell
python train.py
python verify.py --check-reference
```

这条路径会自行生成清洗表、书目表、冻结题名向量、双塔权重和预测结果。复现环境和安装命令见 [README](README.md)。
